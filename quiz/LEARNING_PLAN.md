# 知识问答 · 「从零到掌握」专业学习系统 建设方案 v2

> 目标：把知识问答从「刷题站」升级为**能从 0 开始、系统学会一门知识的独立学习系统**——有课程、有路径、有讲解、有练习、有导师、有掌握认证，刷题只是其中一环。
> 本版为 **方案文档 v2（仅设计，未改代码）**。v1 的「知识卡」思路已被本版推翻——卡片只是零件，不是系统。
> 范围（已确认）：四形态全做（系统课程 / 闯关路径 / AI 导师 / 融合掌握）；**先聚焦电路 + 编程两科**；内容走 AI 生成 + 人工精编；一次性规划；先出文档。

---

## 一、重新定位：这不是「学习功能」，是「学习系统」

v1 的知识卡之所以不够，是因为它只回答了「复习时看什么」，没有回答「一个零基础的人怎么一步步学会」。真正的系统要回答四个问题，对应你确认的四种形态：

| 问题 | 形态 | 系统里的角色 |
|---|---|---|
| 我该按什么顺序学？ | **闯关路径式** | 技能树——知识点按依赖排成路线，过关才解锁下一关 |
| 每个知识怎么从零讲透？ | **系统课程式** | 微课——每节是完整的「零基础→会做」学习单元 |
| 卡住了谁来带我？ | **AI 导师对话** | 苏格拉底式引导——不直接给答案，一步步问答带你推出来 |
| 怎么才算真学会、不忘？ | **融合掌握机制** | 过关测验 + 掌握式解锁 + SRS 长期巩固 |

四者不是四个并列功能，而是**一套系统的四层**：技能树是骨架、微课是血肉、AI 导师是私教、掌握机制是免疫系统。这就是「融合式」。

## 三、核心一：技能树路径（闯关骨架）

### 3.1 数据模型：Course（课程）→ Lesson（节点）

```jsonc
// data/course_circuit.json（权威静态数据，构建期内联）
{
  "id": "circuit", "name": "电路与模拟电子技术", "icon": "🔌",
  "lessons": [
    {
      "id": "c01", "name": "电流、电压与电阻", "kp": "电路基础",
      "deps": [],                          // 前置节点 id，空=起点
      "minutes": 8, "diff": 1,
      "content": { /* 见第四节微课结构 */ },
      "quizPool": "circuit|电路基础",       // 从哪个知识点抽题做过关测验
      "tutorPrompts": [ /* AI 导师预设引导，见第五节 */ ]
    },
    {
      "id": "c04", "name": "串联与并联分析", "kp": "电路基础",
      "deps": ["c01", "c02"],              // 需先掌握电流电压 + 欧姆定律
      ...
    }
  ]
}
```

- `deps` 构成 DAG；解锁规则 = **所有前置节点的过关测验都达标**。
- 分支允许「多条路径汇合」（如电容、交流都解锁后续某节）。
- 每个 Lesson 的 `kp` 关联现有题库 tag，复用 507 题电路题库做过关测验与练习。

### 3.2 节点状态与解锁逻辑（纯函数，进 learn_core）

- 状态：`locked`（前置未过关）/ `available`（可学）/ `learning`（已进入）/ `mastered`（过关达标）。
- 解锁：`unlock(course, progress)` 返回所有前置均 mastered 的节点。
- 推荐：`nextLesson(course, progress)` —— 优先「到期复习节点」，其次「最先解锁的 available 节点」，给「下一步学什么」一个确定答案。
- 循环检测：课程数据校验时断言 `deps` 无环、无悬空引用（进 `_course.cjs`）。

## 四、核心二：系统微课（从零讲透的学习单元）

每个 Lesson 的 `content` 是**七段式教学结构**，这是「从 0 学会」的主体。以电路「串联与并联分析」为例：

| 段 | 名称 | 内容要求 | 数据来源 |
|---|---|---|---|
| ① | 零基础引入 | 生活类比（「串联像一条单行道上的红绿灯，并联像多条车道」）+ 为什么需要它 + 回顾前置 | AI 生成 + 人工精编 |
| ② | 核心概念 | 定义、原理、公式（串联分压 / 并联分流）、配示意图，拆成 2~4 个小块 | AI 生成 + 人工精编 |
| ③ | 分步例题 | 1~2 道完整 worked example，每步标「为什么这么做」，可展开/收起 | AI 生成 + 人工精编 |
| ④ | 易错点 | 2~3 个常见误区（「以为并联电阻越并越大」）+ 错因 + 纠正 | AI 生成 + 人工精编 |
| ⑤ | 形成性练习 | 2~4 道即时反馈小题，答错就地讲原因，不记录 | 现有题库抽取 |
| ⑥ | 过关测验 | 5 题，≥80% 才标记 mastered 并解锁下游；未过可重测（题重新抽） | 现有题库抽取 |
| ⑦ | AI 导师入口 | 「哪里没懂？问我」按钮，进入苏格拉底对话 | 见第五节 |

**关键设计**：
- ②④ 的内容是**静态固化的 JSON**（AI 在实施期生成 + 人工精编后写死），用户离线即可看完整课程，**不依赖运行时联网或用户配 AI**。
- ⑤⑥ 直接复用现有题库和答题引擎（新 `typeKey='b:lesson'`），**不重写判分**——这是这个项目最大的复用点。
- 测验题从 `quizPool` 指定的知识点抽，题量不足时用同课程相邻知识点补足，由 `_course.cjs` 校验每个节点至少有 5 道可用测验题。

## 五、核心三：AI 导师（苏格拉底式引导）

不是「问答机器」，而是**带着学生推导的私教**。设计要点：

- **不直接给答案**：针对本节的核心概念与例题，预设 3~5 轮引导脚本（`tutorPrompts`），由浅入深发问。例如串联分压：「如果两个电阻一样，电压怎么分？→ 如果一个大一个小呢？→ 那电压跟电阻成什么关系？」
- **两步走**：
  - **离线底座**：预设引导脚本 + 关键词应答规则固化在课程 JSON 里，没配 AI 也能用「引导式学习」（这是保底，保证功能不残缺）。
  - **AI 增强**：用户配了 API 时，把 `tutorPrompts` + 本节内容 + 学生当前回答作为上下文，走现有 `QANet` 调 `callAI()`，生成个性化追问；结果缓存 `bt_qa_learn_chat`，可清空重来。
- **约束**：系统提示词强制「不直接说出最终答案、每次只问一个问题、答错时给提示而非结论」——这是「专业导师」和「搜索引擎」的分界线。
- **失败降级**：网络/未配置时自动回落到预设脚本，界面无感知。

## 六、核心四：掌握机制（融合）

把现有的 SRS 和薄弱题上升到「节点」与「知识点」两级：

- **过关 → 解锁**：测验达标 → 节点 mastered → 下游节点解锁。这是掌握式学习（mastery learning）的核心。
- **掌握度分级**：每个节点维护 `lv`（复用 `QALogic.srsAdvance` 的 6 级 1/2/4/7/15/30 天）+ `seen/ok/last`。
- **长期巩固**：「今日复习」= SRS 到期的节点 + 薄弱 TOP3 关联节点，学完回写间隔。学过的节点不会学完就忘。
- **薄弱回流**：微课练习/测验答错的题照常进 `bt_qa_weak`（带 `tag`），可在「薄弱专项突破」里按知识点集中攻克——v1 的这块能力保留为系统的一个下游功能，不再是主体。

## 七、内容生产：AI 生成 + 人工精编（重点，工作量最大）

### 7.1 两科规模

| 学科 | 节点数 | 现有资产 | 内容生产 |
|---|---|---|---|
| 电路 | 46 个知识点（现有 tag） | 507 题、覆盖 46 个知识点 | 按 46 个知识点编 46 节微课；其中高频核心（电路基础、欧姆定律、放大电路、运放、反馈等 ~15 节）人工深度精编，其余 AI 生成 + 人工校对 |
| 编程 | 6 类 tag + 细分子主题（约 20~30 节） | 模板生成题库 + 手写题 | 通识 + 各语言基础 + Web + SQL，核心节人工精编，其余 AI 生成 |

### 7.2 生产流程（实施期，一次性）

1. **定大纲**：人工确定两科的技能树结构（节点、依赖、命名），这是骨架，必须人工把关。
2. **AI 批量生成**：按统一七段式模板 + 统一写作规范（术语、难度、语气、公式格式），逐节生成 `content` 与 `tutorPrompts` 草稿。
3. **人工精编**：核心节逐字精修；其余节校对准确性（尤其公式、数值、解释方向——参考之前 do-while 错题的教训，AI 生成的题解必须验算）。
4. **固化入库**：写入 `data/course_circuit.json` / `course_code.json`，构建期内联。
5. **校验门禁**：`_course.cjs` 断言——deps 无环无悬空、每节七段齐全、每节测验题 ≥5 且可解、kp 与题库 tag 对应、公式/答案与题库一致。

> **质量红线**：AI 生成的内容绝不允许出现「答案与解析矛盾」——实施时必须像验证 do-while 题那样，对每道例题用独立算法/逻辑校验输出。这是「专业系统」的底线。

### 7.3 运行时 AI 导师的内容来源

预设引导脚本（`tutorPrompts`）随课程 JSON 固化，实施期一并生成精编；AI 只做个性化追问增强。**用户不配 AI 也能完整走完引导式学习**。

## 十二、风险与约束

1. **内容是生死线**：系统再漂亮，讲解错了就是误导。执行 P0 样例评审 + P1 逐节验算，尤其公式与例题答案。
2. **范围覆盖**：本版只做电路 + 编程两科（用户确认），其余 10 科的迁移留待系统验证成功后复制，不在本版范围。
3. **AI 依赖可控**：课程正文固化离线；AI 导师有离线脚本保底——用户不配 API 也能完整学习，功能不残缺。
4. **单文件体积**：当前 597 KB；两科课程 JSON（含七段正文）预计 +150~300 KB，gzip 后增幅更小。若过大，按学科拆成按需加载的独立 chunk（SW 预热），但优先保单文件离线形态——实施时实测决策。
5. **窄屏空间**：topbar 已有 4 按钮，加 📖 后小屏做图标收缩或仅保留书架横幅入口，实施时实测。
6. **不发布**：本版仍按之前节奏——全绿后由主理人决定发布时机；本步仅出文档，不涉及构建与推送。
