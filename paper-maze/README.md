# 纸上迷城 · Paper Maze

一座纸做的、写不完的城。纯前端文字解谜 / 密室逃脱：**零依赖、无后端、无 CDN、无图片素材**，
唯一持久化是 `localStorage`，唯一外部输入是你的点击。

```
npm start          # 本地静态服务 → http://localhost:5179
npm test           # node --test tests/*.test.mjs
```

需要 Node ≥ 18（开发用的是 Node 24）。没有构建步骤，改完直接刷新。

## 目录结构

```
PAPER-MAZE/
├── index.html          外壳：HUD / 房间区 / 底部面板 / 弹窗 / 开场遮罩（1 个 module 脚本）
├── styles.css          旧纸 + 墨色 + 一盏灯；安全区、44px 热区、reduced-motion 兜底
├── server.mjs          本地静态服务（零依赖，防目录穿越，正确 MIME）
├── src/
│   ├── story.mjs       纯数据：13 房间 / 40 物品 / 12 配方 / 7 谜题 / 4 结局 / 13 线索
│   ├── engine.mjs      纯逻辑：移动、查看、合成、判定、结局、提示（不碰 DOM / localStorage / 时钟）
│   ├── save.mjs        localStorage 读写 + 版本迁移 + 损坏修复 + 图鉴 + 二周目
│   ├── audio-volume.mjs 主音量：独立键读写 / 夹取 / 唯一增益计算点（静音覆盖音量）
│   ├── ui.mjs          渲染与输入（只把 engine 的结果画出来）
│   └── sfx.mjs         Web Audio 程序化音效（总音量 × 静音，用户手势后解锁）
├── tests/              node:test（7 个测试文件 + 1 个断言计数器）
└── tools/
    └── verify-browser.mjs   开发期可选：用系统 Edge/Chrome 真机跑流程（CDP，零依赖）
```

分层铁律：**逻辑可单测、UI 只渲染**。`engine.mjs` 里没有 `document` / `localStorage` / `Date.now` /
`Math.random`（`tests/engine.test.mjs` 会扫描源码断言这一点），时间一律由调用方注入。

## 玩法与辅助

- **探索**：点热点查看 / 拾取，点出口移动（桌面支持方向键与 `WASD`、`Q` 上 `Z` 下）。
- **合成**：背包里选两件 → 「合成」。工具类物品（蘸墨的笔）合成后不消耗。
- **谜题**：数字用键盘输入，顺序 / 选择用选项按钮，文字用单字输入。
- **日记**：所有看过的线索自动入册，附「已解开的机关」和推导说明。
- **提示**：卡关 90 秒后按钮由倒计时变为可用，给一句方向性提示（文本随进度变化），并累计「提示次数」。
- **音效**：程序化 Web Audio，右上角可拖主音量滑杆、一键静音，遵循「用户手势后解锁」。
  音量存 `papermaze.volume.v1`（设备偏好，独立于存档）；静音存存档 `settings.muted`，
  实际增益 = `muted ? 0 : 音量`，静音只关总闸、不改写玩家调好的音量。
- **留存**：`papermaze.save.v1` 自动存盘（每次动作 + 页面隐藏 + 关闭前）；结局图鉴记录解锁数、
  达成次数与最快用时；支持二周目（继承线索、不继承物品）；重开本局保留图鉴。

## 真实浏览器验证（可选）

`tools/verify-browser.mjs` 用系统自带 Edge/Chrome + CDP（Node 内置 `WebSocket`，不装任何包）跑两条流程并截图：

```powershell
node server.mjs
node tools/verify-browser.mjs http://127.0.0.1:5179/ smoke    # 抓物品 / 开面板 / 解数字锁 / 刷新续档
node tools/verify-browser.mjs http://127.0.0.1:5179/ ending   # 用 UI 走完整通关路线到「焚城」结局
```

实测结果（375×667 移动视口 + 900×800 桌面）：

- 两条流程 **0 条 console 报错 / 0 条未捕获异常**；
- 首屏真实传输字节 **105,478 B ≈ 103.0 KB**（index.html + styles.css + 5 个模块，`encodedBodySize` 实测，
  与磁盘字节数一致）；
- 最小可见按钮高度 **44px**，`scrollWidth` 无横向溢出；设置面板的用时每秒刷新（实测 1.4s 内更新）；
- 最小可见按钮高度 **44px**，`scrollWidth` 无横向溢出；
- 数字锁先故意答错再答对 → 掉落铜刻度盘，弹窗关闭；天平、四座灯台顺序谜题均通过 UI 解开；
- 门厅处「逃出」按钮因缺少复刻钥匙/聚光刻盘而**正确地禁用**，「焚城」可用 → 结局界面 → 图鉴 1/4 → 落盘；
- 刷新后按钮变「继续」，回到书房，丢失物品数 0。

> 顺带一提：这套验证抓出过一个真 bug —— 谜题答错后键盘输入没有清空，玩家第二次按数字会"没反应"。
> 已修（答错即清空输入）。

## 已知问题 / 未实现

1. **音频只验证到增益层**：headless 环境无法断言"确实听到声音"，但已用注入式 `GainNode` 追踪验证
   「拖滑杆 → master.gain 实时变化 / 静音 → 0」，并覆盖不报错与手势解锁路径。
2. **谜题不做硬门槛**：即使在没拿到线索时也能尝试输入（界面会明确提示"你还没有拿到能推出答案的线索"）。
   这是有意为之——不想把玩家锁死，但确实存在穷举猜中的可能（数字锁 3 位、顺序谜题 4! 种）。
3. **焚城结局有前置顺序要求**：点燃的蜡烛在合成"显字纸条"时会被消耗，所以想走焚城结局必须先完成
   地窖与灯堂、但不能先去显字。三条其它结局不受影响。这是设计上的关键取舍，未做额外提示。
4. **合成只支持两件物品**，没有"三物组合"或"对热点使用物品"的交互（物品条件通过持有判定）。
5. **没有 BGM**：只有一套程序化音效参数；主音量滑杆同时作用于所有音效。
6. **无云端/多档位**：只有一个存档槽 + 一个图鉴；清档会连图鉴一起清（已有二次确认）。
7. **没有做 i18n**，全部文案为中文；`index.html` 的 `lang="zh-CN"`。
8. **桌面端未做多栏布局**，只是把移动端外壳居中放宽到 860px（结论性判断：够用，但没有专门的桌面适配）。
